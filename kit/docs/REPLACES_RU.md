# Справочник замен плейсхолдеров

Как заполнить токены `<PLACEHOLDER>` в файлах правил (`AGENTS.md`, `CLAUDE.md`), в навыках
(`.claude/skills/`) и в ролях агентов при переносе **Universal Agent Kit** в свой проект. Это русское зеркало `REPLACES.md` - если команда
читает по-английски, зеркало можно не брать.

Ярусов два. **Первый заполняется всегда.** Второй - только если проект собирается или запускается;
если нет, правила с этими токенами удаляются, а не заполняются выдуманными значениями. Правило,
указывающее на незаполненный плейсхолдер, - самый быстрый способ научить всех пролистывать свод
правил.

Хороший первый шаг после копирования кита: попросить агента найти в нём все токены `<` + `>` и
предложить значение для каждого из реального проекта.

---

## Ярус 1 - любой проект

Эти одиннадцать применимы к любому проекту, у которого есть файлы, единицы работы и проверки.

| Токен | Что это | Софт | Данные и аналитика | Тексты и документация | Юридическое и операционное |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `<PROJECT_NAME>` | Название проекта. | `user-service` | `q3-churn-model` | `platform-handbook` | `acme-msa-2026` |
| `<CHAT_LANGUAGE>` | Язык общения агента с вами. | `English` | `English` | `Russian` | `English` |
| `<ARTIFACT_LANGUAGE>` | Язык файлов, документов, логов и коммитов. | `English` | `English` или язык команды | `Russian` (язык рукописи) | `German` (юридическое: язык юрисдикции; операционное: язык команды) |
| `<INDEX_DOC>` | Карта, которую агент читает первой. | `README.md` | `docs/DATA_DICTIONARY.md` | `SUMMARY.md` | `MATTER_INDEX.md` |
| `<WORK_ROOT>` | Где лежит настоящий материал проекта. | `src` | `pipelines` | `content` | `drafts` |
| `<CHECK_CMD>` | Команда, доказывающая, что правка не сломала работу. Единственный токен, который нельзя оставить пустым. | `npm test` | `make validate` (схема + счёт строк) | `npm run lint:docs` (ссылки, заголовки, термины) | `pwsh tools/check-terms.ps1` |
| `<PLAN_DIR>` | Где лежат спеки и планы. | `PLAN` | `PLAN` | `PLAN` | `PLAN` |
| `<SCRATCH_DIR>` | Черновики и бэкапы, вне контроля версий. | `tmp` | `.scratch` | `tmp` | `tmp` |
| `<SIZE_BUDGET>` | Число строк, после которого файл делится по осмысленному шву. Голое число: `~` и единицу шаблоны дописывают сами. | `500` | `400` | `800` (глава) | `1200` (договор) |
| `<READONLY_ZONES>` | Пути, которые агент никогда не меняет. | `dist, node_modules` | `data/raw` | `locales/generated` | `executed, filed` |
| `<ID_SCHEME>` | Схема идентификаторов тикетов, заполняется один раз. Не путать с `<ID>` - см. ниже. | `T0042` | `AN-042` | `DOC-042` | `M-042` |

### Те, над которыми стоит подумать дважды

**`<CHECK_CMD>`** - самая ценная строка файла. Отвечает на вопрос «какая команда скажет мне, что
правка не сломана», и её чаще всего пропускают - потому что кажется, будто в проекте нет ничего
механического. Обычно это неправда: `PROJECT_SHAPES.md` перечисляет пять форм, которые проверка
принимает в работе, где ничего не компилируется (сумма должна сойтись с другой суммой; имя должно
существовать в другом месте; структура должна держаться; ссылка должна разрешаться; сборка должна
получиться). Поставьте сюда самую дешёвую настоящую проверку, какая есть сегодня, и улучшайте
потом.

**`<INDEX_DOC>`** - это не только то, что читают, но и то, что поддерживают. С него начинается
порядок исследования, поэтому устаревшая карта стоит одного неверного поворота в каждой задаче
(`RESEARCH_INDEX.md`).

**`<CHAT_LANGUAGE>`** и **`<ARTIFACT_LANGUAGE>`** - два токена, потому что разговаривать и сдавать
работу - разные задачи. Язык чата - это то, на чём агент говорит с вами. Язык артефактов - то, на
чём он пишет файлы, документы, логи и коммиты: по умолчанию английский для проекта с кодом, чтобы
проект оставался читаемым для любого, кто в него придёт; юрист, переводчик или аналитик может сдавать
работу на языке самого документа.

**`<READONLY_ZONES>`** - вендоренный код, сгенерированное, сырые данные, всё уже подписанное или
поданное. Если таких зон нет, пишется `none`; пустое значение читается как незавершённое слияние.

**`<SIZE_BUDGET>`** - эвристика «файл делает слишком много», а не закон. Ставьте туда, где начинает
ворчать ваше собственное ревью.

## Ярус 2 - слой кода

Заполняется, если проект собирается или запускается. Если нет - правила с этими токенами удаляются:
правила слоя кода и правило о метках верификации в файле правил (`AGENTS.md`), структурные правила в
`CODE_QUALITY.md` и строки про стек в ролях `implementer` и `rd-lead`.

| Токен | Что это | Frontend / Node.js | Backend (Go / Python) | Mobile (Kotlin / Swift) | Systems (Rust / C++) |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `<ARCH_LAYERS>` | Направление зависимостей. | `page -> widget -> api` | `handler -> service -> repo` | `UI -> VM -> Repo` | `mod -> impl -> core` |
| `<BUILD_CMD>` | Сборка / компиляция. | `npm run build` | `go build ./...` | `./gradlew assemble` | `cargo build` |
| `<TEST_CMD>` | Юнит- и интеграционные тесты. | `npm test` | `pytest` / `go test ./...` | `./gradlew test` | `cargo test` |
| `<LINT_CMD>` | Статический анализ. | `npm run lint` | `golangci-lint run` | `./gradlew lint` | `cargo clippy` |
| `<RUN_CMD>` | Запуск. | `npm run dev` | `python main.py` | `./gradlew installDebug` | `cargo run` |
| `<LOGGER>` | Фасад логирования. | `logger.info` | `logging.info` / `log.Printf` | `Log.d` / `os_log` | `log::info!` |

`<LOGGER>` должен называть настоящий фасад: голый `console.log` / `print` - это ровно то, что
запрещает анти-слоп правило. `<ARCH_LAYERS>` читается слева направо как «может зависеть от»:
`A -> B` значит, что A импортирует B и никогда наоборот. Если слоёв в проекте честно нет, пишется
`n/a`, а не выдуманная схема.

Четыре командных токена - это уточнения `<CHECK_CMD>`, а не замена ему: правила кита берут самую
узкую проверку, доказывающую именно эту правку (`VALIDATION.md`), и заполненные пять токенов - это
то, что позволяет выбрать компиляцию вместо полной сборки.

## Временные шаблонные токены

Это **не** конфигурация. Они заполняются на лету, по ходу работы с навыками:

* `<ID>` - идентификатор одного тикета по схеме `<ID_SCHEME>` (`T0042`); заполняется каждый раз, когда
  создаётся тикет, и никогда - при слиянии кита. Слияние, вписавшее в навыки фиксированный
  идентификатор, ломает каждый тикет после первого.
* `<slug>` - короткое описание тикета через дефис (`add-login-button`).
* `<NN>` / `<NNNN>` - порядковый номер фазы или исследовательского артефакта (`01`, `0042`), не
  идентификатор тикета.
* `<TS>` - метка времени для черновых имён файлов (`20260702_1530`), используется `/prove`.
* `<TODO>` - невыполненный пункт.
* `<symbol>` - имя в материале: класс, функция, колонка, определённый термин.
* `<path>` - путь к файлу или папке.
* `???` - нерешённый вопрос или проверка.
* `$ARGUMENTS` - Claude Code подставляет сюда всё, что вы написали после имени навыка. В других
  инструментах это текст после триггера сохранённого промпта.

## Если у вас более ранняя копия кита

Что переименовано, перенесено или добавлено по сравнению с ранними копиями:

| Было | Стало | Почему |
| :--- | :--- | :--- |
| `<SRC_ROOT>` | `<WORK_ROOT>` | Материал не всегда исходный код. |
| `<MAX_LOC>` | `<SIZE_BUDGET>` | Строки кода - одна единица измерения из нескольких. |
| - | `<CHECK_CMD>` | Общий шаг доказательства, частными случаями которого стали четыре командных токена. |
| `<ID>` (настройка) | `<ID_SCHEME>` | Одно имя делало две работы: схема, заполняемая один раз, и идентификатор одного тикета, заполняемый на каждый тикет. |
| «Артефакты: английский», жёстко | `<ARTIFACT_LANGUAGE>` | Договор или рукопись сдаются на своём языке. |
| `/verify` | `/prove` | Старое имя перекрывало команду, которая есть в самой среде. |
| `/review` | `/critique` | Старое имя перекрывало команду, которая есть в самой среде. |
| `.claude/commands/<name>.md` | `.claude/skills/<name>/SKILL.md` | Навыки - текущий формат среды и единственный, который читают и другие агентные инструменты. |

`<WORK_ROOT>` и `<SIZE_BUDGET>` закрываются автозаменой по вашей заполненной копии. У `<CHECK_CMD>`
нет старого значения: возьмите самую дешёвую проверку, которую вы и так делаете руками, и запишите
её. `<ID>` переименовывается в `<ID_SCHEME>` только там, где он называет настройку, - никогда не
глобально, потому что навыки используют `<ID>` на каждый тикет; если прежнее слияние вписало в
навыки фиксированный идентификатор вроде `T0042`, верните туда `<ID>`. `<ARTIFACT_LANGUAGE>` - новый
токен: значение `English` сохраняет прежнее поведение. Для двух переименованных навыков и переноса
папки скопируйте `.claude/skills/` из нового кита, заполните его плейсхолдеры и удалите старые файлы
`.claude/commands/` - оставленные на месте `/verify` и `/review` продолжат перекрывать собственные
команды среды.
