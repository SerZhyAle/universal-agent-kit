Получить краткое сообщение коммита для вставкиGet a terse Conventional Commit message to pasteОтримати стисле повідомлення коміту для вставки

/caveman-commit формирует одно сообщение коммита: заголовок в формате Conventional Commits, короткий, и тело только тогда, когда причина неочевидна. Он опирается на ваше описание, а если описания нет, на текущие git diff и git status. Он создаёт сообщение и больше ничего./caveman-commit generates one commit message: a subject in Conventional Commits format, kept short, and a body only when the reason is not obvious. It works from your description or, when you give none, from the current git diff and git status. It generates the message and nothing else./caveman-commit формує одне повідомлення коміту: заголовок у форматі Conventional Commits, короткий, і тіло лише тоді, коли причина неочевидна. Він спирається на ваш опис, а якщо опису немає, на поточні git diff і git status. Він створює повідомлення і більше нічого.

Когда это нужноWhen to reach for itКоли це потрібно

Изменение вам уже понятно, и нужно быстро получить сообщение коммита без лишнего шума.The change is already understood and you want a quick commit message without noise.Зміна вам уже зрозуміла, і потрібно швидко отримати повідомлення коміту без зайвого шуму.

Прежде чем начатьBefore you startПерш ніж почати

Команда только формирует сообщение. Она не запускает git commit, не добавляет файлы в индекс и не изменяет историю, так что сам коммит остаётся за вами.The command generates the message only. It does not run git commit, stage files or amend history, so committing stays with you.Команда лише формує повідомлення. Вона не запускає git commit, не додає файли до індексу й не змінює історію, тож сам коміт лишається за вами.

ШагиStepsКроки

  1. Введите /caveman-commit, чтобы сообщение вывелось из текущего diff, или добавьте контекст: /caveman-commit fix retry on network thumbnail. Строка вызова: /caveman-commit [optional: context].Type /caveman-commit to infer the message from the current diff, or add context: /caveman-commit fix retry on network thumbnail. The usage line is /caveman-commit [optional: context].Введіть /caveman-commit, щоб повідомлення вивелося з поточного diff, або додайте контекст: /caveman-commit fix retry on network thumbnail. Рядок виклику: /caveman-commit [optional: context].
  2. Если вы описали изменение, агент берёт ваше описание. Если нет, он изучает текущие git diff и git status и выводит сообщение из них.If you described the change, the agent uses your description. If you did not, it inspects the current git diff and git status to infer the message.Якщо ви описали зміну, агент бере ваш опис. Якщо ні, він вивчає поточні git diff і git status та виводить повідомлення з них.
  3. Он пишет заголовок в формате Conventional Commits, type(scope): imperative summary, область (scope) необязательна. Предпочтение отдаётся типам feat, fix, refactor, perf, docs, test, chore, build, ci, style и revert.It writes the subject in Conventional Commits format, type(scope): imperative summary, with the scope optional. It prefers the types feat, fix, refactor, perf, docs, test, chore, build, ci, style and revert.Він пише заголовок у форматі Conventional Commits, type(scope): imperative summary, область (scope) необов'язкова. Перевага віддається типам feat, fix, refactor, perf, docs, test, chore, build, ci, style і revert.
  4. Заголовок называет видимое пользователю изменение, а не механизм: fix(export): keep page breaks in PDF invoices, а не fix(export): flush stream before close.The subject names the user-visible change, not the mechanism: fix(export): keep page breaks in PDF invoices, not fix(export): flush stream before close.Заголовок називає видиму користувачеві зміну, а не механізм: fix(export): keep page breaks in PDF invoices, а не fix(export): flush stream before close.
  5. Он держит заголовок кратким: ориентир 50 символов и меньше, жёсткий предел 72, точки в конце нет.It keeps the subject terse: a target of 50 characters or fewer, a hard cap of 72, no trailing period.Він тримає заголовок стислим: орієнтир 50 символів і менше, жорстка межа 72, крапки в кінці немає.
  6. Тело он добавляет только тогда, когда причина неочевидна из заголовка, и всегда для критических изменений совместимости, исправлений безопасности, миграций данных и откатов, даже если это стоит лишних слов. Строки тела короткие, перенос около 72 символов.It adds a body only when the why is not obvious from the subject, and always for breaking changes, security fixes, data migrations and reverts, even if that costs more words. Body lines are concise and wrapped near 72 characters.Тіло він додає лише тоді, коли причина неочевидна із заголовка, і завжди для змін, що ламають сумісність, виправлень безпеки, міграцій даних та відкатів, навіть якщо це коштує зайвих слів. Рядки тіла стислі, перенесення близько 72 символів.
  7. Указание авторства, например строка соавтора или трейлер инструмента, - выбор команды, который фиксирует файл правил проекта, и агент ему следует. Если файл молчит, агент спрашивает вас один раз, записывает ответ в файл правил и следует ему. Авторство он никогда не добавляет и не убирает молча.Attribution, such as a co-author line or a tool trailer, is a team choice that the project's rules file states, and the agent follows it. If the file says nothing, it asks you once, writes your answer into the rules file and follows it. It never adds or strips attribution silently.Зазначення авторства, наприклад рядок співавтора чи трейлер інструмента, - вибір команди, який фіксує файл правил проєкту, і агент його дотримується. Якщо файл мовчить, агент питає вас один раз, записує відповідь у файл правил і дотримується її. Авторство він ніколи не додає й не прибирає мовчки.
  8. Он не добавляет пустых фраз и выводит сообщение блоком кода, готовым к вставке. Очевидный diff не пересказывается.It leaves out filler phrases and prints the message as a fenced code block, ready to paste. The obvious diff is not explained.Він не додає порожніх фраз і виводить повідомлення блоком коду, готовим до вставки. Очевидний diff не переказується.

Блок кода с одним сообщением коммита, например fix(thumbnail): retry on network error, и телом для тех случаев, где оно нужно. Ничего не добавлено в индекс и ничего не закоммичено.A fenced code block holding one commit message, for example fix(thumbnail): retry on network error, plus a body for the cases that need one. Nothing is staged and nothing is committed.Блок коду з одним повідомленням коміту, наприклад fix(thumbnail): retry on network error, і тілом для тих випадків, де воно потрібне. Нічого не додано до індексу й нічого не закомічено.

СоветыTipsПоради

  • Сообщение пишется на языке, который ваш проект задал в <ARTIFACT_LANGUAGE> - плейсхолдере файла правил, - на каком бы языке ни шёл чат.The message is written in the language your project set as <ARTIFACT_LANGUAGE>, a placeholder of the rules file, whatever language the chat is in.Повідомлення пишеться мовою, яку ваш проєкт задав у <ARTIFACT_LANGUAGE> - плейсхолдері файлу правил, - якою б мовою не йшов чат.
  • Если сначала нужно разбить неразобранное рабочее дерево на несколько коммитов, воспользуйтесь руководством по git, а затем попросите сообщение для каждой группы.To split a messy working tree into several commits first, use the git guide, then ask for a message for each group.Якщо спершу потрібно розбити неперебране робоче дерево на кілька комітів, скористайтеся посібником із git, а потім попросіть повідомлення для кожної групи.
  • Это не режим всего чата. /caveman делает кратким весь чат, /caveman-review делает то же для ревью, а эта команда пишет только сообщение коммита.This is not the chat-wide mode. /caveman makes the whole chat terse, /caveman-review does the same for a review, and this command only writes the commit message.Це не режим усього чату. /caveman робить стислим увесь чат, /caveman-review робить те саме для рев'ю, а ця команда пише лише повідомлення коміту.
