Получить ревью изменений: одна строка на замечаниеReview a diff with one terse line per findingОтримати рев'ю змін: один рядок на зауваження

/caveman-review - прямой и быстрый проход по изменению. Он проверяет по обычной планке, сначала баги, риски, регрессии и недостающие тесты, и выводит замечания до любого резюме, по одной строке на замечание, пока это остаётся ясным. Для более полного прохода используйте /critique./caveman-review is the blunt, fast pass over a change. It reviews at the normal bar, with bugs, risks, regressions and missing tests first, and prints findings before any summary, one line per finding where that stays clear. For the fuller pass, use /critique./caveman-review - прямий і швидкий прохід по зміні. Він перевіряє за звичайною планкою, спершу баги, ризики, регресії та бракуючі тести, і виводить зауваження перед будь-яким підсумком, по одному рядку на зауваження, поки це лишається ясним. Для повнішого проходу використовуйте /critique.

Когда это нужноWhen to reach for itКоли це потрібно

Нужен прямой и быстрый взгляд на diff: замечания, а не развёрнутый отчёт, без вступлений и похвал для объёма.You want a blunt, fast look at a diff: findings and not a write-up, with no throat-clearing or praise padding.Потрібен прямий і швидкий погляд на diff: зауваження, а не розгорнутий звіт, без вступів і похвал для об'єму.

Прежде чем начатьBefore you startПерш ніж почати

Краткость - это формат, а не сниженная планка. Если однострочный комментарий скрыл бы важный контекст безопасности, архитектуры или разрушительного риска, либо проблема связана с безопасностью или архитектурно нетривиальна, ревью переходит на короткий абзац вместо принудительного сжатия до одной строки.Terse is a format, not a lower bar. When a one-line comment would hide important security, architectural or destructive-risk context, or the issue is security-sensitive or architecturally non-trivial, the review switches to a short paragraph instead of forcing one-line compression.Стислість - це формат, а не знижена планка. Якщо однорядковий коментар приховав би важливий контекст безпеки, архітектури чи руйнівного ризику, або проблема стосується безпеки чи архітектурно нетривіальна, рев'ю переходить на короткий абзац замість примусового стискання до одного рядка.

  3. Он выводит замечания до любого резюме, по одной строке на замечание, пока ясность сохраняется. Строка начинается с файла и номера строки, затем идёт метка: bug, risk или nit с проблемой и исправлением либо q с вопросом. Например: PaymentService.cs:L42: bug: refund runs twice on retry. Add an idempotency key.It prints findings before any summary, one line per finding when clarity is preserved. A line starts with the file and the line number, then a label: bug, risk or nit followed by the problem and a fix, or q followed by a question. For example: PaymentService.cs:L42: bug: refund runs twice on retry. Add an idempotency key.Він виводить зауваження перед будь-яким підсумком, по одному рядку на зауваження, поки ясність зберігається. Рядок починається з файлу й номера рядка, далі йде мітка: bug, risk або nit з проблемою та виправленням чи q із запитанням. Наприклад: PaymentService.cs:L42: bug: refund runs twice on retry. Add an idempotency key.
  4. Символы, имена файлов, номера строк, команды, API и тексты ошибок остаются точными. Совет без конкретного направления, например голое предложение провести рефакторинг, недопустим: каждое замечание применимо на практике и технически точно.Exact symbols, file names, line numbers, commands, APIs and error strings stay unchanged. Advice with no concrete direction, such as a bare suggestion to refactor, is not allowed: every finding is actionable and technically exact.Символи, імена файлів, номери рядків, команди, API й тексти помилок лишаються точними. Порада без конкретного напрямку, наприклад голе пропонування зробити рефакторинг, неприпустима: кожне зауваження придатне до дії й технічно точне.

Если замечаний нет, ревью прямо об этом говорит и коротко называет оставшиеся пробелы в тестах или проверке.If there are no findings, the review says so explicitly and briefly names the residual test or validation gaps.Якщо зауважень немає, рев'ю прямо про це каже й коротко називає залишкові прогалини в тестах чи перевірці.

СоветыTipsПоради

  • /critique - более полный проход, с замечаниями, сгруппированными по важности. Для краткого вывода по одной строке на замечание kit отсылает к этой команде./critique is the fuller pass, with findings grouped by severity. For terse one-line-per-finding output the kit points to this command instead./critique - повніший прохід, із зауваженнями, згрупованими за важливістю. Для стислого виводу по одному рядку на зауваження kit відсилає до цієї команди.
  • Ревью пишется на языке чата, если только вы не попросите готовые к вставке комментарии для PR: они пишутся на языке, который ваш проект задал в <ARTIFACT_LANGUAGE> - плейсхолдере файла правил.The review is written in the chat language, unless you ask for paste-ready PR comments: those go in the language your project set as <ARTIFACT_LANGUAGE>, a placeholder of the rules file.Рев'ю пишеться мовою чату, якщо тільки ви не попросите готові до вставки коментарі для PR: вони пишуться мовою, яку ваш проєкт задав у <ARTIFACT_LANGUAGE> - плейсхолдері файлу правил.
  • Чтобы кратким был каждый ответ в чате, а не только ревью, включите /caveman. Для сообщения коммита есть /caveman-commit.To make every reply in the chat terse, not only the review, use /caveman. For a commit message there is /caveman-commit.Щоб стислою була кожна відповідь у чаті, а не лише рев'ю, увімкніть /caveman. Для повідомлення коміту є /caveman-commit.
