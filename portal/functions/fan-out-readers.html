Запустить независимые поиски параллельно и проверить результатRun independent lookups in parallel and check what comes backЗапустити незалежні пошуки паралельно й перевірити результат

Читатели распараллеливаются свободно: лишние читатели стоят только токенов. Поиск по локальным символам и запрос внешней документации по одному вопросу стартуют одновременно, а при наличии субагентов каждый читает свой источник. Здесь: бюджетный шлюз перед волной, защита основного контекста от громоздких свидетельств и проверка отчёта дочернего агента оркестратором, прежде чем ему верить.Readers fan out freely, because extra readers cost only tokens. A local symbol search and an external docs fetch answering one question start in the same breath, and with subagents each reads a different source. This page covers the budget gate that comes before a wave, keeping bulky evidence out of the main context, and trusting a child's report only after the orchestrator has checked it.Читачі розпаралелюються вільно: зайві читачі коштують лише токенів. Пошук за локальними символами і запит зовнішньої документації за одним питанням стартують одночасно, а за наявності субагентів кожен читає своє джерело. Тут: бюджетний шлюз перед хвилею, захист основного контексту від громіздких свідчень і перевірка звіту дочірнього агента оркестратором, перш ніж йому вірити.

Когда это нужноWhen to reach for itКоли це потрібно

У вопроса несколько независимых источников, например локальный код, документация фреймворка и открытые issues, либо проверка пойдёт по множеству находок, либо громоздкие свидетельства копятся в вашем контексте.A question has several independent sources, such as local code, framework docs and open issues, or a verification pass would run over many findings, or bulky evidence is piling up in your context.У питання кілька незалежних джерел, наприклад локальний код, документація фреймворку й відкриті issues, або перевірка піде по безлічі знахідок, або громіздкі свідчення накопичуються у вашому контексті.

Прежде чем начатьBefore you startПерш ніж почати

Ошибиться в веере дёшево, только пока каждый помощник лишь читает. Как только в волне появляется пишущий, лишние работники стоят потерянной работы, а не токенов: сначала прочтите, как запустить нескольких пишущих агентов, не потеряв работу.Fan-out is cheap to get wrong only while every helper is read-only. The moment a wave contains a writer, extra workers cost lost work, not tokens: read how to run several writing agents without losing work first.Помилитися у віялі дешево, лише поки кожен помічник тільки читає. Щойно в хвилі з'являється той, хто пише, зайві працівники коштують втраченої роботи, а не токенів: спершу прочитайте, як запустити кількох агентів, що пишуть, не втративши роботи.

ШагиStepsКроки

  1. Перед каждой волной пройдите бюджетный шлюз. Он охватывает число, стоимость, потолок, явное GO выше потолка, порядок «сначала найти, потом проверить» и то, что делать с волной, которую убрал лимит. Всё это описано на странице бюджетного шлюза, а не здесь.Pass the budget gate before every wave. It covers the count, the cost, the ceiling, an explicit GO above it, finding before verifying, and what to do with a wave a limit killed. All of it lives in the budget gate page, not here.Перед кожною хвилею пройдіть бюджетний шлюз. Він охоплює кількість, вартість, стелю, явне GO вище за стелю, порядок «спершу знайти, потім перевірити» і те, що робити з хвилею, яку вбив ліміт. Усе це описано на сторінці бюджетного шлюзу, а не тут.
  2. Запускайте независимые поиски одновременно, а не по очереди. Поиск по локальным символам и запрос внешней документации, отвечающие на один вопрос, не ждут друг друга.Start independent lookups in the same breath, never in sequence. A local symbol search and an external docs fetch that answer the same question do not wait for each other.Запускайте незалежні пошуки одночасно, а не по черзі. Пошук за локальними символами і запит зовнішньої документації, що відповідають на одне питання, не чекають одне одного.
  3. Если в вашей среде есть субагенты, дайте каждому свой источник: один читает локальный код, другой документацию фреймворка, третий смотрит открытые issues. Реальное время вы тратите один раз, а не три.If your runtime has subagents, give each one its own source: one reads the local code, another the framework docs, a third checks open issues. You spend wall-clock once instead of three times.Якщо у вашому середовищі є субагенти, дайте кожному своє джерело: один читає локальний код, інший документацію фреймворку, третій дивиться відкриті issues. Реальний час ви витрачаєте один раз, а не тричі.
  4. Не пускайте громоздкие свидетельства в родителя. Каждый такой элемент прогоняйте в одноразовом дочернем агенте, который возвращает короткий вердикт: артефакты остаются у него, а не копятся в контексте родителя. Изоляция - рычаг бюджета контекста, а не только способ распараллелить.Keep bulky evidence out of the parent. Run each bulky-evidence item in a throwaway child that returns a compact verdict, so the artifacts stay in the child instead of piling up in the parent's context. Isolation is a context-budget lever, not only a way to go parallel.Не пускайте громіздкі свідчення в батьківський агент. Кожен такий елемент проганяйте в одноразовому дочірньому агентові, який повертає короткий вердикт: артефакти лишаються в нього, а не накопичуються в контексті батьківського. Ізоляція - важіль бюджету контексту, а не лише спосіб розпаралелити.
  5. Когда волна вернулась, пусть оркестратор перепроверит результат централизованно. Отчёт дочернего агента - утверждение, а не вердикт, и в обе стороны: сообщённый сбой часто оказывается призраком устаревшей инкрементальной сборки, а сообщённый успех вроде «собирается изолированно» никто не проверял на слитом дереве.When the wave returns, let the orchestrator re-validate centrally. A child's report is a claim, not a verdict, in both directions: a reported failure is often a phantom from a stale incremental build, and a reported success such as "compiles in isolation" was never checked against the merged tree.Коли хвиля повернулася, нехай оркестратор централізовано перевірить результат. Звіт дочірнього агента - твердження, а не вердикт, і в обидва боки: повідомлений збій часто виявляється примарою застарілої інкрементальної збірки, а повідомлений успіх на кшталт «збирається ізольовано» ніхто не перевіряв на злитому дереві.
Что вы должны увидетьWhat you should seeЩо ви маєте побачити

Бюджетный шлюз пройден, независимые поиски шли вместе, громоздкие свидетельства остались у одноразовых дочерних агентов, а оркестратор сверил отчёт каждого дочернего агента со слитым деревом, прежде чем ему поверить.The budget gate was passed, the independent lookups ran together, bulky evidence stayed in throwaway children, and the orchestrator checked each child's report against the merged tree before believing it.Бюджетний шлюз пройдено, незалежні пошуки йшли разом, громіздкі свідчення лишилися в одноразових дочірніх агентів, а оркестратор звірив звіт кожного дочірнього агента зі злитим деревом, перш ніж йому повірити.

СоветыTipsПоради

  • Волна читателей, пошедшая не так, оборачивается счётом, поэтому бюджетный шлюз идёт первым. Его порядок «сначала найти, потом проверить» заодно не даёт платить дважды за одну и ту же проверку.A wave of readers that goes wrong produces a bill, which is why the budget gate comes first. Its find-before-verify staging also keeps you from paying twice for the same check.Хвиля читачів, що пішла не так, обертається рахунком, тому бюджетний шлюз іде першим. Його порядок «спершу знайти, потім перевірити» заодно не дає платити двічі за ту саму перевірку.
  • Полный перечень опасностей делегирования (перекос в сторону хвоста, дочерние агенты, которых нельзя возобновить, состязательная проверка находки) лежит в ролевом брифе оркестратора, rd-lead.The delegation hazards in full (tail bias, non-resumable children, adversarial verification of a finding) are in the orchestrator's role brief, rd-lead.Повний перелік небезпек делегування (перекіс у бік хвоста, дочірні агенти, яких не можна відновити, змагальна перевірка знахідки) лежить у ролевому брифі оркестратора, rd-lead.
  • Порядок поиска отсылает сюда за тем, как распараллелить читателей: см. научить агента искать, а не угадывать. Для работы без присмотра см. пустить работу без присмотра циклом свежих процессов.The research order points here for how to fan readers out: see make the agent look things up instead of guessing. For unattended runs, see run unattended work as a loop of fresh processes.Порядок пошуку відсилає сюди за тим, як розпаралелити читачів: див. навчити агента шукати, а не вгадувати. Для роботи без нагляду див. пустити роботу без нагляду циклом свіжих процесів.

  • Пустить работу без присмотра циклом свежих процессовRun unattended work as a loop of fresh processesПустити роботу без нагляду циклом свіжих процесівДрайвер вне сессии отдаёт по одному рабочему элементу свежему headless-процессу, а состояние хранится в файлах, поэтому каждый элемент начинается с пустого контекста.A driver outside the session feeds one work item at a time to a fresh headless process, with state kept in files, so each item starts on an empty context.Драйвер поза сесією віддає по одному робочому елементу свіжому headless-процесу, а стан зберігається у файлах, тож кожен елемент починається з порожнього контексту.
  • Поручить нетривиальную работу ведущему агентуHand a non-trivial job to a lead agentДоручити нетривіальну роботу ведучому агентовіОдин ведущий агент ведёт запрос от первого чтения до проверенной работы: оценивает задачу, выбирает самый лёгкий подходящий путь и передаёт части другим агентам.One lead agent takes a request from first read to verified work: it classifies the job, picks the lightest path that fits and hands parts to other agents.Один ведучий агент веде запит від першого читання до перевіреної роботи: оцінює завдання, обирає найлегший придатний шлях і передає частини іншим агентам.
  • Назначить бюджет перед параллельным запуском агентовSet a budget before you fan outПризначити бюджет перед паралельним запуском агентівОцените число агентов и примерную цену в токенах, держите потолок около 6-8 агентов и просите явное GO выше него.Estimate the agent count and the rough token cost, keep a ceiling of about 6-8 agents, and ask for an explicit GO above it.Оцініть кількість агентів і приблизну ціну в токенах, тримайте стелю близько 6-8 агентів і просіть явне GO вище неї.
  • Научить агента искать, а не угадыватьMake the agent look things up instead of guessingНавчити агента шукати, а не вгадуватиФиксированный порядок поиска и, для большого проекта, поддерживаемый индекс вашего материала: каждый путь, символ и API, названные агентом, проверены.A fixed order for finding things and, for a big project, a maintained index of your material, so every path, symbol and API the agent states has been verified.Фіксований порядок пошуку і, для великого проєкту, підтримуваний індекс вашого матеріалу: кожен шлях, символ і API, названі агентом, перевірені.
