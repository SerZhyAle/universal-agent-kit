examples/ описывает вымышленный проект user-service и один его тикет, T0042: администратор скачивает список пользователей файлом CSV. Вы читаете спеку, индекс плана, один файл фазы и блок аудита в том виде, какой они имеют по окончании работы, а затем заполненный фрагмент файла правил. Каждое значение в нём принадлежит вымышленному проекту, а не вашему, и ничто в kit эти файлы не читает.examples/ describes an imaginary project, user-service, and one ticket in it, T0042, which lets an admin download the user list as a CSV file. You read its spec, plan index, one phase file and audit block as they look when the work is done, then a filled excerpt of the rules file. Every value in it belongs to the imaginary project and not to yours, and nothing in the kit reads these files.examples/ описує вигаданий проєкт user-service і один його тікет, T0042: адміністратор завантажує список користувачів файлом CSV. Ви читаєте спеку, індекс плану, один файл фази та блок аудиту у тому вигляді, який вони мають по завершенні роботи, а потім заповнений уривок файлу правил. Кожне значення в ньому належить вигаданому проєкту, а не вашому, і ніщо в kit ці файли не читає.

Когда это нужноWhen to reach for itКоли це потрібно

У вас есть kit, но законченного тикета вы ещё не видели, или вы собираетесь заполнять файл правил и хотите увидеть, как выглядят заполненные значения. Также когда тикет стоит на BlockNeedUserTest и вы сомневаетесь, не ошибка ли это.You have the kit but have not seen a finished ticket yet, or you are about to fill the rules file and want to see what filled values look like. Also when a ticket stands at BlockNeedUserTest and you wonder whether that is a mistake.У вас є kit, але завершеного тікета ви ще не бачили, або ви збираєтеся заповнювати файл правил і хочете побачити, як виглядають заповнені значення. Також коли тікет стоїть на BlockNeedUserTest і ви сумніваєтеся, чи це не помилка.

СоветыTipsПоради

  • Значения во фрагменте взяты из столбца «Software» файла docs/REPLACES.md и его столбца Node.js для слоя кода: читайте их рядом. Чтобы заполнить свои, см. заполнить плейсхолдеры; чтобы написать сам файл, см. файл правил.The excerpt's values come from the 'Software' column of docs/REPLACES.md, with its Node.js column for the code layer: read the two side by side. To fill your own, see fill the placeholders; to write the file itself, see the rules file.Значення в уривку взято зі стовпця «Software» файлу docs/REPLACES.md та його стовпця Node.js для шару коду: читайте їх поруч. Щоб заповнити свої, див. заповнити плейсхолдери; щоб написати сам файл, див. файл правил.
  • BlockNeedUserTest - состояние, которое понимают неверно чаще всего. Это не провал и ещё не конец: сборка исправна, а одно, что может увидеть только человек, ещё не увидено. Статус блокировки держится, пока человек не отметит строку и тикет не пройдёт аудит заново.BlockNeedUserTest is the state most often misread. It is not a failure and not yet done: the build is sound, and one thing only a person can see has not been seen. The block status stays until that person ticks the line and the ticket is audited again.BlockNeedUserTest - стан, який розуміють хибно найчастіше. Це не збій і ще не кінець: збірка справна, а одне, що може побачити лише людина, ще не побачене. Статус блокування тримається, доки людина не позначить рядок і тікет не пройде аудит знову.
  • Не путайте examples/ с memory/examples/: там по одному образцу записи памяти на каждый тип, и большинство из них не про код. Эта папка описана на странице сохранить то, чему агент научился, до следующей сессии.Do not confuse examples/ with memory/examples/, which holds one sample memory entry per type, most of them not about code. That folder is described on the page keep what the agent learns from one session to the next.Не плутайте examples/ із memory/examples/: там по одному зразку запису пам'яті на кожен тип, і більшість із них не про код. Цю теку описано на сторінці зберегти те, чого агент навчився, до наступної сесії.
